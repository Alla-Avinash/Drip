what is Node.js 
    what is Node.js written in? 
        Node.js is mainly written in C and C++
        some small featrues of node.js are written in javascript 
        Core engine → C/C++
        Some built-in APIs → JavaScript
    what is the use of node.js? 
        - it is a javascript runtime env 
        - it is used to run javascript
        - it uses system api's to use the system calls to the low level system API's like accessing file system and other features 
    It uses:
        V8 engine (written in C++) to execute JavaScript
        C/C++ code to interact with the operating system (files, network, etc.)

platform builds?
    Node.js → precompiled binary (you download it)
        Node.js is written in C/C++. So:
            There is a Windows build of Node
            A Linux build of Node
            A macOS build of Node
        These are all precompiled binaries that you download.
        When you install Node using the official installer, You’re not compiling anything, You’re downloading a ready-made build for your OS
        Why you don’t compile Node yourself? Because the Node team already does it for you: They compile Node for each platform and distribute them as prebuilt binaries for the differnt platforms
    Your JS code → runs inside Node (no compile)
        Your JavaScript code:
            is not compiled ahead of time
            is interpreted/executed by Node (V8 engine)
        That’s why it works across platforms without recompiling
    Native addons → search if there are precompiled binaries for your platform or you will have to compile locally for compatibility
        Native modules (C/C++) are built on your machine
        Because they must match:
            your Node version
            your OS
            your CPU architecture


why do node use some native libraries in C++/C ??    
    node engine => v8 engine is made up of c++ 
    here node also uses system API for file system and other operations 
    but these native libraries are different from these system API/system calls
    For simple Electron apps you can use just Node.js + system APIs. Most small apps do.
    sometimes Native modules act as a bridge between JS and system APIs
    But VS Code is huge, performance-heavy, and extensible:
        Needs fast file watching in large projects
        Needs low-latency UI updates
        Needs extension host communication
    Pure JS/system APIs are too slow for these workloads. Native modules make things fast.

    there are some native libraries which are used by the node.js env for some of its functionality
    They expose functions that JS code can call directly in machine code.
    Without them, JS alone is much slower for things like:
        File system watchers
        High-performance text search
        Git operations
        Compression or encryption

    some of these native libraries (source code) have prebuilt packages for the platform which you are running 
        prebuilt binaries (.node files)

    Because prebuilt binaries are only available if:
        exact OS matches (Windows/Linux/macOS)
        exact architecture matches (x64, ARM)
        exact Node/Electron version matches

        If ANY of these don’t match:
            fallback → build from source (using C++ tools)

Dev mode vs packaged mode in electron.. 
    In dev mode, you never produce an .exe.
    You run Electron pointing at the compiled output in out/.
    Packaging (.exe) happens only if you run a full release build, which is separate.

    Why dev build cannot just produce .exe like a tiny Electron app?
    In dev, you want:
        Hot reload
        Continuous TypeScript compilation
        Testing extensions
    If you just pre-build an .exe, you can’t test live changes or watch TS files.
    Native modules still need compilation before Electron can use them—even in dev.


general electron applications can easily get converted into .exe files or general installer files according to the platform specified by you...
so tell me why do vscode application need something extra like visual studio build tools for converting into an installer file?? 
    Node modules and TypeScript code need to be compiled to JS and native modules need to be built for your OS.
    native modules exit => these dependencies include C++ code (e.g., file watchers, search helpers, Git integration).
        Electron can’t run C++ directly—you need MSVC + Windows SDK to compile them into .node binaries.
    Code OSS source is in TypeScript, not plain JS.
    You need Node + npm + tsc (TypeScript compiler) to transform the TS code into JS that Electron can execute.


Visual Studio Build Tools
    Visual Studio Build Tools is a lightweight version of Visual Studio that only installs the compiler, linker, and libraries—you don’t need the full IDE. 
    It’s used to build native code modules that Node.js or Electron depends on.
    we need the “Desktop development with C++” for the application
    Why “Desktop development with C++”??
        Some npm dependencies in Code OSS have native C++ components (for example, text search, Git integration, or performance-critical modules).
        Node.js uses node-gyp to compile these modules on your machine.
        The “Desktop development with C++” workload provides:
            MSVC compiler
            Windows SDK
            C++ build tools

Can you use other C++ compilers? instead of the ones in visual studia build tools?
    In theory, yes—any compiler that can build Windows binaries for Node.js can work.
    In practice, Node.js on Windows expects MSVC (Visual Studio compiler) for ABI compatibility with Node’s V8 engine and headers.
    Using MinGW or others often causes build failures or runtime crashes.

how to setup fnm?? and understanding the basic operations of fnm

    fnm needs to inject environment variables into your shell
    Without that → it can’t control Node versions
    run this in your powershell once 
    ~ fnm env --use-on-cd | Out-String | Invoke-Expression

    fnm changes the node version used => only inside that current terminal (shell), not your whole system permanently

    If a project has .nvmrc:
    ~ fnm use
    Automatically switches to required Node version

    If you enable auto-switch
    ~ fnm env --use-on-cd
    When you cd into a folder:
        fnm reads .nvmrc
        switches Node version automatically

    What “inject environment variables into your shell” means
        Your terminal (PowerShell) runs with a set of variables like:
        PATH = where programs are located
        When you type:
            node -v
        PowerShell looks inside PATH to find which Node to run
        What fnm needs to do
            fnm works by changing which Node version is active.
            To do that, it must:
                modify the PATH
                point it to a different Node version folder
        What “inject” means here
            When you run:
            ~ fnm env
            fnm prints commands like:
            set PATH=...fnm\node-versions\...
            But PowerShell does NOT apply them automatically.
            inject ==> fnm is inserting its configuration into your current terminal session
