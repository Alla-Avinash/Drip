About DRIP

DRIP is a plain-text personal knowledge base plus a project tracker, built to help you record — in plain English — what you've built, why, and what still needs doing. Your notes stay as ordinary files on disk; DRIP indexes them so they can be searched, sorted, and browsed.

The two note formats

DRIP reads two kinds of notes. Both live in your knowledge base folder; choose whichever fits how you write.

.d.txt.d.md
What it isDRIP's native plain-text format — metadata, tags, and headings as text lines.Standard Markdown with a rich WYSIWYG editor, DRIP details kept in hidden comments.
Best forFast, keyboard-first writing; tight control over the file.Longer, prose-heavy notes you want to read and edit like a document.
EditingIn the normal text editor, with coloring and completion.In DRIP's visual editor (chips, pickers, headings).

You set the default new-note type (and which extensions appear in the KB) in Knowledge Base.

Getting started, step by step

  1. Pick your format. In Knowledge Base, choose the default new-note extension (.d.txt or .d.md).
  2. Choose a knowledge base folder. A .driplock folder holds all your notes; DRIP indexes it automatically.
  3. Write and capture notes. Type in the editor, or press Ctrl+Shift+U to capture the current selection into the Composer.
  4. File the note. The Composer (or the Chat) sends the note to the right place in the KB — merge into a matching heading, append, or start a new heading.
  5. Track work. Use Projects for projects → features → issues, and the Project View to browse them.
  6. Search and reuse. Use the Retriever to search by meaning, and the Tags Graph to see how tags connect.

Update/reindex the current KB working space

Keeps the existing index.drip. Runs reconcile-update on notes currently in the working KB (honors .dripignore). Colliding @fN values that already belong to another existing file get a new id.

Reset/reindex the entire KB driplock folder

Deletes index.drip, creates a fresh database, then reconcile-updates every note in the driplock folder (including ignored paths, except .dripindex). File ids that collide while rebuilding are assigned from scratch.

KB Metadata

Document KB types

Heading metadata types for the note zone (marker, shortcut, attributes). The type list is fixed — .concept, .task, .issue, .decision. You can add or edit keys (attributes) on these types, but cannot add new types.

Project Metadata

Default project template

Project (.p), feature (.f), and issue (.issue / i) types. Shortcuts are fixed. Issues are headings inside project folders; their metadata (status, priority, deadline, category, parent i-N) feeds Project View. Per-project changes add keys or change enum values; built-in keys cannot be deleted.

Tags & Relations

Manage relation rows (default locked: tags) and descriptions.

Markdown

Manage markdown marks (defaults: L, Q, R). A mark is written in the document as Mark: text — for example Q: why does this work?. Names are case-sensitive — Impl, impl, and IMPL are distinct. L is locked and includes a link format example. Leave a color empty to use the normal text color.

Doc Coloring

The six document colors follow your theme by default. Set a color here to override that specific one in .d.txt notes; leave it empty to keep the theme color.

Embeddings

DRIP always uses sentence embeddings (Transformers.js + ONNX in the extension host) to rank Storage targets — top folder suggestions, next folder/file picks inside a folder, and AI deep-match across the KB.

DRIP uses the Xenova/all-MiniLM-L6-v2 sentence-transformer model. The first use downloads the model weights (~90MB) into the DRIP extension folder (.cache/transformers) — not your home folder's Hugging Face cache — so uninstalling the DRIP extension removes the model files cleanly.

Lightweight LLM

DRIP runs its own small LLM (separate from VS Code Copilot) to decide where a Quick Capture note belongs: merge into the best matching heading, append as a new section, or start a new heading. Only the note plus a short snippet of the top matching headings is sent, keeping tokens low. Each provider profile keeps its own API key in VS Code Secret Storage — never in settings.

Works with any OpenAI-compatible endpoint (OpenAI, Groq, Ollama, LM Studio, …). Examples: https://api.openai.com/v1, https://api.groq.com/openai/v1, http://localhost:11434/v1.

GitHub backup

Back up this knowledge base’s notes to a GitHub remote. The regenerable .dripindex/ folder is ignored. Never store a GitHub password here — use HTTPS + Git Credential Manager / gh auth, SSH keys, or an optional PAT (Secret Storage).

MCP connection

Let AI apps (Cursor, Claude, VS Code Copilot, Windsurf, …) read and manage your DRIP projects and issues. DRIP runs one local MCP server; every MCP-capable app connects to the same address with the same token — no per-app integration. The server only listens on this computer (127.0.0.1) and DRIP must stay open while an app uses it.

How an app uses DRIP

					
Apps see two tools: search_tools (describe what you want, get the matching DRIP tools and their exact inputs) and call_tool (run one). This keeps prompts small while the AI can still reach every DRIP tool. A knowledge base must be open in DRIP.
